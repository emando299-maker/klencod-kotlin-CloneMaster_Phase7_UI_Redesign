# CloneMaster Phase 5 — محرك تجريبي لتعديل Package Name

## ما الجديد؟
- يظل استخراج APK وفحصه وتصديره موجودًا.
- أضفنا زر **إنشاء APK معدل وتوقيعه** بعد اختيار ملف APK.
- المحرك يحاول تعديل قيم اسم الحزمة داخل `AndroidManifest.xml` الثنائي، ثم يزيل ملفات التوقيع القديمة ويعيد توقيع الملف بمفتاح محلي مؤقت.
- بعد نجاح العملية يظهر زر تصدير APK الناتج.

## طريقة التجربة على Kleancode
1. افتح المشروع كاملًا من ملف ZIP.
2. اعمل Sync/Build وانتظر تنزيل الاعتماديات الجديدة.
3. افتح CloneMaster، واضغط «اختيار APK لفحصه» واختر APK واحدًا (ليس split APK).
4. أدخل Package Name جديدًا مثل `com.example.game.clone`.
5. اضغط «إنشاء APK معدل وتوقيعه» وانتظر النتيجة.
6. إذا نجحت العملية، صدّر الملف إلى التنزيلات. سيطلب Android تأكيدًا منك عند تثبيته.

## حدود مهمة جدًا
- هذه نسخة تجريبية؛ لم يتم اختبار البناء على Kleancode أو جهاز Android في بيئة التطوير هذه.
- التعديل يغيّر Manifest فقط، ولا يغيّر اسم العرض أو الأيقونة حتى الآن.
- بعض التطبيقات تحتوي اسم الحزمة في ملفات DEX أو موارد أخرى أو تستخدم تحققًا من التوقيع/Play Integrity؛ قد لا تعمل بعد التعديل.
- ملفات split APK / App Bundle غير مدعومة؛ استخراج `base.apk` وحده لا يكفي لهذه التطبيقات.
- التوقيع الجديد مختلف عن توقيع التطبيق الأصلي، لذلك لا يمكن تثبيته كتحديث فوق التطبيق الأصلي؛ استخدم Package Name مختلفًا.
- المحرك لا يتجاوز حماية التطبيقات ولا يضمن استنساخ أي تطبيق.
- مفتاح التوقيع في هذه المرحلة مؤقت ويتجدد مع كل عملية؛ لا تستخدم هذه النسخة لتحديث نسخ معدّلة سابقة.

## المكتبات الجديدة
- `com.android.tools.build:apksig:8.7.3` لإعادة التوقيع.
- `org.bouncycastle:bcpkix-jdk18on:1.80` لإنشاء شهادة توقيع محلية.


## إصلاح المرحلة 5.1
تمت إضافة استثناء لمسار ملف META-INF المكرر أثناء دمج موارد Java في app/build.gradle.kts. هذا يعالج خطأ البناء الظاهر في سجل Kleancode، لكن يجب إعادة البناء للتأكد من نجاحه في بيئتك.


## المرحلة 5.2 — تشخيص عدم التوافق
- يكتشف المحرك الآن إذا كان التطبيق المثبت يستخدم split APKs ويوقف العملية برسالة واضحة بدل إنتاج ملف ناقص.
- يتحقق من الحد الأدنى لإصدار Android المعلن في APK.
- هذا لا يحول التطبيقات متعددة الأجزاء إلى APK واحد؛ دعم split cloning يحتاج معالجة كل split وإعادة بناء/توقيع الحزمة كاملة.


## المرحلة 5.3 — دعم تطبيقات split (base + splits)
- عند اختيار APK لتطبيق مثبّت كعدة ملفات، يجمع المحرك كل ملفات split من التطبيق المثبت تلقائيًا (بشرط تطابق رقم الإصدار).
- يعدّل `AndroidManifest.xml` في كل ملف، ويوقّع الجميع بنفس المفتاح (شرط أساسي لتثبيت split).
- زر جديد **تثبيت النسخة** يثبّت كل الملفات معًا عبر PackageInstaller، وزر **تصدير حزمة .apks** لحفظها.
- إصلاح: لم تعد أسماء الـ Activities/Application تُغيَّر (كانت تسبب تعطل التطبيق)؛ يتم تغيير `package` وأسماء الـ authorities والصلاحيات الخاصة فقط.
- إصلاح: يُحفظ `resources.arsc` والمكتبات غير مضغوطة ومحاذاة (مطلوب في Android 11+).
- أُضيف إذن `REQUEST_INSTALL_PACKAGES`.
- ملاحظة: لم يُبنَ المشروع هنا؛ أعد البناء على Kleancode وأبلغ بأي خطأ.


## المرحلة 6
- **اسم العرض:** تغيير `android:label` للتطبيق ولأنشطة الإطلاق (LAUNCHER).
- **الأيقونة:** اختيار صورة من المعرض؛ يعاد توجيه موارد الأيقونة في `resources.arsc` (كل الكثافات) إلى PNG مضاف للحزمة، ويُطبّق على base وكل split.
- **مفتاح توقيع ثابت:** يُحفظ داخل التطبيق ويُستخدم لكل النسخ، فيمكن تحديث نسخة مثبتة بنسخة أحدث بنفس الـ Package Name. (حذف Clone Master أو مسح بياناته يفقد المفتاح.)
- **تنظيف التخزين:** عرض أحجام الملفات وزر حذفها.
- **واجهة جديدة داكنة:** ثلاثة تبويبات (التطبيقات / النسخ / الإعدادات)، أيقونات التطبيقات الحقيقية، والضغط على تطبيق يجهّزه مباشرة للنسخ.
- أُزيلت «خطط النسخ المحفوظة» لأنها كانت ملاحظات فقط بلا تأثير.
- لم يُبنَ المشروع في بيئة التطوير؛ أعد البناء على Kleancode وأبلغ بأي خطأ.


## إصلاحات CloneMaster Phase 6.1
- إصلاح تعارض Kotlin بين خاصية `source` ودالة `setSource` بإعادة تسمية الدالة إلى `updateSource`.
- معالجة تعارض `ContentProvider authorities`: كل Authority في كل Provider يعاد توليدها داخل نطاق فريد مشتق من Package Name الجديد وبصمة SHA-256 للقيمة الأصلية. تتم قراءة قيمة النص الخام أيضًا قبل تصفية أنواع القيم، لأن بعض ملفات APK لا تعرض Authority كـ `TYPE_STRING` في الحقل typed data. يدعم ذلك القيم المتعددة المفصولة بفاصلة منقوطة.
- الاسم الناتج ثابت لنفس التطبيق ونفس Package Name، لكنه يختلف بين النسخ ذات Package Names المختلفة.
- تنبيه توافق: تغيير Authority يمنع تعارض أسماء المزوّدات على مستوى النظام، لكنه قد يؤثر على تطبيق يعتمد كوده على الاسم القديم حرفيًا أو يمرر الاسم إلى تطبيقات أخرى. تعديل Manifest وحده لا يضمن توافق كل تطبيق؛ يلزم اختبار التثبيت والتشغيل ومشاركة الملفات وتسجيل الدخول.


### Phase 6.2 – إصلاح قراءة Provider Authorities
- تم نقل معالجة `android:authorities` قبل شرط `TYPE_STRING` واستخدام rawValue عند توفره، مع تحديث rawValue وtypedValue معًا.
- يتم تغيير كل Authority بما فيها أسماء مزودي Facebook وTikTok الخارجية، وليس فقط الأسماء التي تبدأ باسم الحزمة الأصلية.
- لم يتم اعتبار الإصلاح ناجحًا نهائيًا قبل بناء المشروع واختباره على الجهاز.
